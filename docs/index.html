Text-to-speech currency

Currency amounts a speech synthesizer reads correctly.

moneyspeak turns a currency amount into a string a speech synthesizer reads correctly. The digits are left to the engine; what it supplies is the currency words.

USD 123.45 · en-US → “123 US dollars and 45 cents”

The problem

USD123.45 becomes “US dollars” on some engines, and SGD123.45 is spelled out on others. The synthesizer’s text normalizer decides, and it is engine-specific.

Install

pnpm add moneyspeak

Unpublished prototype. moneyspeak is not on the npm registry yet, so pnpm add moneyspeak will not resolve. Install it from the repository for now.

Quickstart

Two entry points. moneyspeak resolves amounts and verbalizes them; moneyspeak/dom renders them accessibly in the browser. This documentation app imports the TypeScript source directly, so the examples below stay in sync with the code. 

import { resolveCurrency, verbalizeMoney, parseMoney } from "../src/index.js";
import { setAccessibleMoney, defineCurrencyAmount, srOnlyCss } from "../src/dom.js";

Published builds import from moneyspeak and moneyspeak/dom. The .js specifiers in the source tree resolve to the .ts files under Vite. 

import { verbalizeMoney } from "moneyspeak";

const result = verbalizeMoney({ amount: 123.45, currency: "USD", locale: "en-US" });

result.spoken;   // "123 US dollars and 45 cents"
result.display;  // "$123.45"
result.strategy; // "major-minor"
result.warnings; // []

resolveCurrency exposes everything the spoken form is built from, and where each value came from. 

import { resolveCurrency } from "moneyspeak";

const resolved = resolveCurrency("SGD", "en-US");
resolved.exponent; // 2
resolved.subunit;  // { one: "cent", other: "cents" }
resolved.order;    // "prefix"
resolved.split;    // true
resolved.sources;  // { name: "intl", exponent: "intl", subunit: "data" }

The invariant: spoken never contains a bare ISO code or a currency symbol.

Data

Everything that can be derived comes from Intl at runtime. Two things Intl cannot give are shipped as data, and that is the entire maintenance surface.

data/subunits.json

Minor unit names. CLDR has none, so the library ships them: cent, paise, satang, sen, and so on.

Keys are ISO 4217 codes, then BCP 47 language subtags. A null entry marks a currency with no minor unit, such as JPY.

This is draft data. Each entry is a claim to check against the currency’s issuing authority and the locale’s usage.

data/overrides.json

Only the entries where the value derived from Intl is missing or reads badly:

  • exponent corrections, for example IDR as 2 where the runtime resolves 0
  • name overrides, for example id-ID USD → dolar Amerika
  • per-locale connector and split, for example the de connector und, or split: false for zh, ja, and th

Derived from Intl at runtime

  • the currency name, singular and plural, via formatToParts at 1 and 2
  • the symbol, the word order, and the digits and separators
  • the fraction digits, via resolvedOptions().maximumFractionDigits

Accessibility

setAccessibleMoney renders the conventional form for sighted users and the spoken form for assistive technology, keeping the amount in one text node so the digits survive as a single token. 

import { setAccessibleMoney } from "moneyspeak/dom";

setAccessibleMoney(el, { amount: 123.45, currency: "SGD", locale: "en-SG" });

A custom element wraps the same helper. Register it once, then use it in markup. 

import { defineCurrencyAmount } from "moneyspeak/dom";

defineCurrencyAmount();
<currency-amount amount="123.45" currency="SGD" locale="en-SG"></currency-amount>

The hidden spoken span uses srOnlyCss, which the docs page also injects: 

.moneyspeak-sr{position:absolute;width:1px;height:1px;padding:0;margin:-1px;overflow:hidden;clip:rect(0,0,0,0);white-space:nowrap;border:0;}

Limits

  • Output follows the runtime’s CLDR, so it can differ between browsers and Node versions, and can change without notice when those datasets update.
  • Subunit names are draft data, not CLDR, and need review before release.
  • The synthesizer still normalizes the digits. moneyspeak supplies the currency words and leaves number reading to the engine.
